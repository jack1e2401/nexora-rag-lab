# RAG Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. User requested one continuous run, verification before commits, and several thematic commits afterward.

**Goal:** Complete fixed-token ingestion, grounded RAG query, and paired evaluation.

**Architecture:** The benchmark files are staged under `data/benchmark`. A synchronous CLI creates immutable profile snapshots in pgvector. FastAPI exposes search and ask. A second CLI runs paired benchmark cases and records local plus optional Langfuse results.

**Tech Stack:** Python 3.11+, FastAPI, Tika, psycopg/pgvector, local BGE-M3, DeepSeek HTTP API, Langfuse SDK.

**Spec:** `docs/superpowers/specs/2026-10-27-rag-flow-design.md`

## Global Constraints

- `fixed_token` only; no LLM chunker.
- One pinned BGE-M3 model and 1024-dimensional vectors for documents and queries.
- DeepSeek only for generation and any judge calls.
- Exclude `SECURITY` from primary benchmark scores; preserve skipped counts.
- Verify all code before making multiple thematic commits.

## Review Focus

- Changed source files must not silently mix profiles from different corpora.
- A model revision mismatch must fail before search.
- Hallucinated source labels must not appear as verified citations.
- Gold answers and gold document IDs must never enter generation prompts.
- A failed ingest must preserve the previously stored profile.
